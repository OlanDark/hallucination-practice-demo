# Как дать преподавателю доступ к коду и веб-приложению

**Результат:** 2 ссылки — публичный GitHub-репозиторий с полным кодом и веб-приложение на `streamlit.app`.

## Шаг 1. Создать репозиторий GitHub

1. Откройте https://github.com/ и войдите в свой аккаунт (или зарегистрируйтесь).
2. Откройте https://github.com/new
3. Repository name: `hallucination-practice-demo` (или другое имя).
4. Visibility: **Public** — для просмотра преподавателю аккаунт не нужен.
5. Нажмите **Create repository**. Если GitHub предлагает заранее добавить README, не обязательно отмечать: README уже есть в комплекте.

## Шаг 2. Загрузить исходники

1. Распакуйте скачанный ZIP на своём компьютере.
2. В пустом репозитории выберите **uploading an existing file** или **Add file → Upload files**.
3. Откройте распакованную папку и выделите **всё её содержимое** (а не саму папку): `app.py`, `agents.py`, `pipeline.py`, `wiki_search.py`, `llm.py`, `config.py`, `experiment.py`, тесты, `requirements.txt`, `README.md`, `.gitignore` и этот документ.
4. Перетащите выбранные файлы в окно GitHub, нажмите **Commit changes**.
5. Убедитесь, что `app.py` и `requirements.txt` находятся в КОРНЕ репозитория, а не в дополнительной вложенной папке.

Важно: **НЕ загружайте ZIP как единственный файл** — тогда Streamlit не увидит `app.py`.

Не добавляйте `.env`, папки `cache`, `venv`, `data`, `results`, журнал экспериментов или секретный API-ключ. `.gitignore` не гарантирует защиту, если файлы вручную добавлены через веб-интерфейс.

## Шаг 3. Опубликовать приложение в Streamlit Cloud

1. Откройте https://share.streamlit.io/
2. Войдите и подключите свой GitHub.
3. Нажмите **Create app**, затем **Yup, I have an app**.
4. Repository: выберите созданный репозиторий.
5. Branch: `main` (или другую ветку, если она фактически использована).
6. Main file path: **`app.py`**.
7. Откройте **Advanced settings** и в поле **Secrets** вставьте:

```toml
GROQ_API_KEY = "ваш_настоящий_ключ_Groq"
```

Только в Secrets сервиса, не в GitHub, не в файл проекта и не в чат.
8. Сохраните настройки, нажмите **Deploy**.
9. Откройте полученный URL вида `https://...streamlit.app` и проверьте оба режима.

## Шаг 4. Проверить со стороны преподавателя

В браузере без входа в GitHub откройте публичную страницу репозитория: файлы должны быть видны.
В браузере без входа в Streamlit откройте ссылку приложения, введите тестовый текст, запустите проверку, убедитесь, что показаны результаты и источники.

**Преподавателю отправьте две ссылки:**

- `https://github.com/<ваш_логин>/<имя_репозитория>` — код.
- `https://<выбранное_имя>.streamlit.app/` — запущенное приложение.

## Если возникла проблема

- **ModuleNotFoundError** → проверьте `requirements.txt` и расположение `.py` рядом с `app.py`.
- **Не найден API-ключ** → проверьте точное имя `GROQ_API_KEY` в Streamlit Secrets и перезагрузите приложение.
- **Groq 429 / rate limit** → исчерпан лимит или слишком много запросов; проверьте квоты Groq.
- **Википедия 429/403** → источник временно ограничивает запросы; повторите позже, проверьте логи.
- **Приложение «спит»** → Streamlit может остановить неактивное приложение; первое открытие потребует времени на пробуждение.
- **В браузере видно код вместо приложения** → отправлена ссылка GitHub, а не Streamlit. Нужны две разные ссылки.

## Важное о доступе и расходах

Публичное приложение доступно всем, кто знает ссылку. Запросы посетителей выполняются с использованием вашего Groq-ключа, сохранённого в облачных настройках, и расходуют ваши лимиты. Не публикуйте ключ и проверяйте текущие лимиты. При необходимости отключите приложение после защиты.
